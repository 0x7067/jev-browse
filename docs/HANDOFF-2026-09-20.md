Branch: `claude/jev-browser-openrouter-capabilities-0fcyus`. No `src/` changes
were made; this branch adds this handoff and the probe scripts under
`scripts/probes/` that produced the evidence below.

## Blocker: no live Jev run was possible

The `TYPESAFE_AI_KEY` available in the session is rejected by TypeSafe's own
API (`POST https://api.typesafe.ai/v1/systemone` → 401 with curl, independent
of jev-browse). Two things to fix before the next session:

1. Issue a valid key at console.typesafe.ai/settings/keys.
2. Export it as `TYPESAFE_API_KEY` — the SDK and `src/env.ts` read that name,
   not `TYPESAFE_AI_KEY`.

The OpenRouter key works (`inception/mercury-2.5` answers in ~175 ms).

## Environment fixes that were session-only (redo them)

- Chrome trusted the egress proxy only after importing its CA into the NSS
  store: `apt-get install libnss3-tools` then
  `certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n proxy -i /root/.ccr/agent-proxy-ca.crt`.
  Before that, every https page rendered Chrome's "Privacy error" and the
  snapshot reported it as an ordinary page.
- `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` — discovery
  in `src/cdp/chrome.ts` does not read `PLAYWRIGHT_BROWSERS_PATH`.
- Hosts blocked or broken from this container: github.com and pypi.org
  (proxy policy), lite.duckduckgo.com (upstream failure), www.w3.org
  (Cloudflare challenge; the `challenge` flag fired correctly).

## What was verified without Jev

**Driver machinery** (`scripts/probes/machinery.ts`, `machinery3.ts`): 14/14
scripted flows on `fixture-interactions.html` pass through the real CDP driver,
~330 ms per action: shadow click, iframe click, modal confirm, hover menu,
disabled-until-input, type+Enter, native select, date fill, range via
click+arrows, new-tab adoption, drag, context click, download tracking.

**Extractor** (`scripts/probes/probe.ts`): all 77 unique task URLs across the
four tiers observed; median observe 1.4 s, p90 2.3 s; shadow and framed
controls pierced on MDN and jQuery UI.

**Text helper** (`scripts/probes/helper-test.mjs`): 18/18 valid JSON answers.
mercury-2.5 175 ms median; gemini-2.5-flash-lite 409 ms and once truncated
"tomsmith" → "tomsmit"; gpt-4.1-nano 479 ms.

**Historical evals** (60 result files, base tier only): strong on hn, tin-login,
fixtures, books/lobsters/wikipedia; weak on sauce-checkout (13/27 verified),
todomvc-add (15/34), tin-drag-drop, flights (28/39). The hard/harder/hardest
tiers (66 tasks) have never had a result file recorded.

## Gaps found

- First observation races SPA hydration: crates.io returned in 9 ms with zero
  text and 29 in-flight requests; 3 s later 986 chars / 47 controls. Costs a
  decision on WAIT.
- Fixed action-space overhead: 17–22 offered actions on even a one-select page
  (all PRESS_*, scroll, wait, back, forward always listed).
- chrome-error:// and challenge pages are not short-circuited; decisions are
  spent on them.
- Hover targets can carry junk labels (fixture: "Hover 7. Modal confirm Delete
  draft Really de").
- 16 base-tier tasks have no `expect` and report `unverifiable`.

## Suggested next steps, in order

1. Valid key → `node scripts/eval.mjs --repeat 3` on all four tier files;
   record counts and result paths per AGENTS.md.
2. Bounded first-paint/network-idle wait before the first decision (~1.5 s).
3. Fast path: chrome-error URL or `challenge` → `blocked` with reason.
4. Honor `PLAYWRIGHT_BROWSERS_PATH` in Chrome discovery.
5. Give unverifiable tasks an `expect` or drop them.

Run the probes with `CHROME_PATH=... node scripts/probes/<file>`;
`helper-test.mjs` takes OpenRouter model ids as arguments and needs
`OPENROUTER_API_KEY`.
